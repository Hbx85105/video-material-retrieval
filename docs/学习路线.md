## 核心原则

师兄的需求文档里有三条设计约束，是整个项目的"宪法"：

1. **先验证检索链路，再加理解能力，最后做剪辑价值。** 不要一上来就把 CLIP、YOLO、Whisper 全装上。
2. **不自研通用能力。** 解码用 FFmpeg，向量库用 Qdrant，全部拿现成的，只自研"事件划分"和"价值排序"两处。
3. **CPU 优先。** 不依赖显卡。

对你个人的原则：**每天要有可提交的产出**，哪怕很小。不会就问 AI，但要读懂它写的代码。

## Day 1 补充：怎么把项目推到 GitHub

1. 注册/登录 GitHub，点右上角 `+` → `New repository`
2. 仓库名填 `video-material-retrieval`，其他默认，**不要**勾选初始化 README
3. 创建后会看到一段命令，复制类似下面这段，在项目目录的 cmd 里执行：

```bash
git remote add origin https://github.com/你的用户名/video-material-retrieval.git
git branch -M main
git push -u origin main
```

4. 如果提示登录，按提示用浏览器授权即可。
5. 刷新 GitHub 页面，能看到文件就成功了。

> 这一步卡住正常，把报错原文发给 AI，或照着提问模板问。

## Git 最常用命令

| 命令 | 作用 | 什么时候用 |
| --- | --- | --- |
| `git status` | 看哪些文件改了 | 随时 |
| `git add .` | 把所有改动加入待提交 | 提交前 |
| `git commit -m "说明"` | 保存一个版本 | 每天结束 |
| `git push` | 推到 GitHub | 想备份/展示时 |
| `git log --oneline` | 看提交历史 | 想看自己做了多少 |

记住一个心法：commit 就是游戏存档。每天存一次档，出问题能回退。

## Python 最小必要语法

看懂 `probe_video.py` 需要的全部语法，就这些：

```python
# 1. 变量：给数据起个名字
name = "雨天车窗"

# 2. 字典：一对一的表格，用 key 取值
info = {"分辨率": "640x360", "帧率": 25}
print(info["分辨率"])        # 输出 640x360

# 3. 列表：一串数据
files = ["a.mp4", "b.mp4"]

# 4. for 循环：对列表里每个东西做同样的事
for f in files:
    print(f)

# 5. 函数：把一段代码打包起名字
def add(a, b):
    return a + b

result = add(1, 2)           # result = 3

# 6. if 判断
if result > 2:
    print("大于2")
else:
    print("不大于")
```

能看懂这六段，就能看懂项目里 90% 的代码。其余遇到再查。

## FFmpeg / ffprobe 常用命令

```bash
# 读一个视频的全部元数据（JSON 格式）
ffprobe -v error -print_format json -show_format -show_streams 视频.mp4

# 每秒抽 1 帧，输出成图片
ffmpeg -i 视频.mp4 -vf fps=1 frame_%03d.jpg

# 生成一个测试视频（没素材时用这个）
ffmpeg -f lavfi -i "testsrc=size=640x360:rate=25:duration=4" \
       -f lavfi -i "sine=frequency=440:duration=4" \
       -c:v libx264 -pix_fmt yuv420p -c:a aac -shortest -y sample_test.mp4
```

## 阶段一技术依赖安装

按顺序装，一条一条来，装完一条再装下一条。失败了把报错发 AI。

```bash
# 1. PyTorch CPU 版（不带显卡支持，体积小）
pip install torch --index-url https://download.pytorch.org/whl/cpu

# 2. 向量数据库（本地模式，不需要服务器）
pip install qdrant-client

# 3. 图像处理
pip install pillow numpy
```

> Chinese-CLIP 的安装稍复杂（需要从 GitHub 装），放到第 8 天再做，到时候单独问。

## 怎么读陌生代码

AI 给了一段代码你看不懂？按这个顺序拆：

1. **先看函数签名**：`def xxx(a, b):` —— 它叫什么、要什么输入
2. **再看 return**：最后返回什么 —— 这决定了它的用途
3. **中间逐行**：遇到不认识的函数，单独问 AI "这一行的 xxx 是什么意思"
4. **动手改**：把参数改一改，看输出怎么变，这是最快的理解方式

不要试图一次读懂全部。读懂 80% 就够往下走了，剩下 20% 会在后面自然明白。
